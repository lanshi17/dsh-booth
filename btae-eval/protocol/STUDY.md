# Pilot 实验协议草案 v0.1

本协议为预注册前草案，不是已登记或已完成的研究。阶段目标是检验实验可行性、方差和成本，允许结论为无差异、负效应或无法估计。

## 1. 问题与比较

研究问题：在相同模型、执行框架、可访问信息、工具权限和生命周期预算下，结构化类/实体设计、追溯、架构演进、证据门禁与上下文治理能否改善持续维护？

主比较 E（完整 BTAE）对 C（SDD 风格），唯一主要终点为**维护轮次功能成功率的配对差**。A、B、D 的比较以及影响 F1、架构、成本均为预设次要/解释性分析。本次 Pilot 只做效应与不确定性估计，不作确认性优越宣称。

C 为本研究冻结的 Spec Kit 风格流程；不是直接运行官方工具的等效性证明。Kiro 商业产品若加入，另列产品实验，明确其模型/内置提示不可控，不能与受控方法比较混为因果证据。

## 2. 任务和统计单位

候选集：queue、ledger、artifact、reservation，均为小型合成 Python 仓库，每仓库连续 6 轮，共 24 条请求。T1 新功能、T2 接口传播、T4 边界修复、T3 接口解耦/第二适配器；本轮没有 T5 多 Agent 证据。

一条处理轨迹 = 仓库 × 组别 × 重复，整条轨迹保持同组。60 条轨迹、360 个 round episode。它们不等于 360 个独立实验单位。task 属于仓库，重复属于 task/轨迹，轮次是相关重复测量。第一轮从完全相同的源摘要开始；后续轮次沿各自实际代码演进，不从统一正确实现重置。

同一 task/repeat 的五组组成配对区块；每轮内部随机化处理顺序，使用归档的 SplitMix64 种子；每条轨迹中轮次有序。独立上下文/工作区/日志，不共享其他组的解决方案或记忆。此设计是**并行处理的匹配区块设计**，不是让同一个有记忆 Agent 依次体验五种方法的 crossover。

原始仓库摘要定义为排序后的 [相对路径, 文件 SHA256] 列表的紧凑 JSON 的 SHA256；文件清单存入 datasets/*-snapshot.json。正式纳入的真实仓库还必须固定 commit、许可证及容器 digest。

## 3. 主要终点和权重

维护轮次 = 第 2、3、4、6 轮；第 1、5 轮为新增功能，独立报告。一次成功必须：在预算内完成、通过冻结的独立验收条件与全部规定的隐藏回归检查；Agent 自报完成/自己新建测试通过不足以成功。

先在每仓库的同一轮对重复运行求均值，再对维护轮等权求均值，最后对仓库等权。主效应 = mean_repository(E − C)。不按 token、测试数量或仓库 LOC 给更多权重。隐藏测试的数量不能使某任务拥有更高权重。

主要任务集、排除标准和分母在运行前固定；所有计划运行均进入清单。没有观测的运行记为缺失，不直接伪造为失败或删除。正式效果计算在配对完整性审计后进行；对行政缺失单独报告原因/数量，并做最坏/最好界限敏感性分析。Agent 失败、超时、预算耗尽是研究结果，成功=0且保留成本。运行基础设施故障单列，是否重跑按共同预案决定；原失败记录不可覆盖。

## 4. 预算和信息公平性

候选预算每次 round episode 总输入+输出 token 60000、wall 1800 秒、最多 2 次尝试、1 Agent。**这些是可行性参数，正式开跑前校准并冻结。**重试不得重置预算。缓存 token 是输入子集，不另加一次；平台未计费隐式思考要记录计量限制，不能假装全量可见。

五组相同 commandcode/deepseek/deepseek-v4.1-flash 与 DSH headless；环境、模型参数、上下文压缩、MCP 集、工具权限和人工帮助流程相同，只有机制实现不同。每轮总预算覆盖设计、索引、上下文检索、编码、验证和文档维护，不给 BTAE 免费预处理。五组可读取相同任务/代码/公共文档，E 的 Resolver 只能选择子集，不能拿到私有标注或额外正确答案。

基线不禁止 Agent 自发设计/测试/写文档；其自然行为必须记录。B 的“人工维护文档”由同样受限的 Agent 执行；如使用人类维护，必须五组同规则、计时计费并单独报告人机混合干预。

## 5. 次要指标

- 影响：在修改前冻结预测集。Precision/Recall/F1 基于统一语义实体真值；当前候选仅有文件级真值草案，不能据此证明类级 H2。分层报告实现/契约/测试/已有文档，不要求 A 生成 BTAE 专属文件。空分母=null；报告有效样本数，不把无变更任务记为满分。
- 架构：规则在五组开始前共同冻结，检查导入方向、内部状态越界、接口契约。ADS=sum(w*v)/sum(w*r)，违规数≤检查机会数；零机会=null，同时公开逐规则原始分子分母和不加权率。不能只用总分。新增代码可能膨胀分母，需另报相对于固定初始机会集的违规、违规密度和新增机会数。
- 维护：回归缺陷/计划变更数、返工工时/总工时、各轮累计成本；MTTR 未修复者为右删失，不把未解决项丢弃。当前 Rust CLI 未实现生存分析。
- 成本：模型账单+计算费用+人类时间×冻结单价；各项互斥，失败和重试也计入。设计/文档/审核/返工/维护/验证是上述成本的**阶段分解**，不能再加一次重复计费。wall-clock 与人类/Agent 工时分别报，避免并行时间重复计数。
- 过程：机制遵守率、事前设计、链接有效性、审批/测试证据，只解释处理是否发生，不用“遵守 BTAE 规范”定义功能质量优劣。

## 6. 推断和胜负

Pilot 使用配对仓库簇 bootstrap 给出效应和探索性 95% 区间，先聚合重复与轮次再抽样仓库；4 个合成且相似的仓库不足以得到可靠泛化或功效保证。bootstrap 无法补救小簇数或任务选择偏差。实现仅接受外部审计后的仓库级配对均值，没有自动结果收集/缺失数据修复。

正式研究按预实验估计仓库/任务/重复的相关结构，用模拟确定仓库数、任务数和重复数。混合效应模型需包含方法、轮次及交互和适当随机效应；McNemar 只适用于真正独立的单次二分类配对，不能把本设计 360 条运行直接塞进去。Wilcoxon 不绕过聚类。额外比较/假设使用 Holm 校正并给区间；未预注册的子组仅作探索。

候选的工程阈值供正式冻结前讨论：维护成功率最小有意义提升 +5 个百分点；成本可接受上界比值 1.20。它们还不是已认可的领域标准，不以此计算已通过/失败。确认性研究才可在预先规定的区间与多重性规则下同时检验质量优势和成本非劣；“成本差异不显著”不等于成本不增加。另报告 Pareto 分布和受失败分母影响的单位成功成本；若无成功成本比为未定义。

研究可能得到：E 更准但更贵；追溯更好而功能无差异；简单项目负收益；特定模型/规模有效。均应保留，不使用未经预注册的加权总分选冠军。
