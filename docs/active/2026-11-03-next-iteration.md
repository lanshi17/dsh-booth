## 当前不建议推进的事项

- 不把一次 DSH 工程任务成功当作 BTAE 方法成功，也不把 69 条公开契约断言当作隐藏评估。
- 不在 P1/P2 未关闭前扩大到 20–30 个任务、五组和三次重复。
- 不用 Worker 自报的 token 代替 provider 账单；本轮成功复测的 123,729 tokens 已超过草案 60,000 预算，只能作为工程验收。
- 不把 DSH 部署目录的符号链接修复写进 Rust 研究结果；升级后必须重新运行模块身份检查。
- 不将 Superagent Forge 的协议/持久化实现与 BTAE-Eval 的研究结果混为同一验收项。

## 最近一次可执行迭代

下一次编码前，先完成 P1 的一个垂直切片：选择 M3 双向追溯，给 C、D、E 三组各实现一个最小任务适配器，输出统一的设计实体、代码实体、测试实体和变更影响集合。随后用一个未参与实现的检查器运行正例和负例。只有这个切片能在独立输入下稳定区分缺失、错误和正确追溯，才继续扩展到 M1、M4、M5、M6。

该切片的交付物应为：

1. 冻结后的机制规格和任务输入摘要。
2. 三组基线适配器及其版本摘要。
3. 独立检查器、一个已知坏输入和一个已知好输入。
4. 机器可读的结果、运行成本和失败原因。
5. 一份明确写出 `NOT RUN` 或 `blocked` 的验收报告。

完成这些交付物后，再更新 [BTAE-Eval 路线图](../../btae-eval/protocol/ROADMAP.md) 的 P1 状态；在此之前保持 `DRAFT / NOT RUN` 和 readiness 阻断。
