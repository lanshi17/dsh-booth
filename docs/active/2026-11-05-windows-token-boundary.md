# Windows 删除边界修复决策

**Status:** selected route B; implementation in progress
**Created:** 2026-11-05
**PR:** #12，保持草稿

## 已验证的问题

在受保护且继承 Everyone 全权 ACL 的目录中，生产 legacy 令牌会拒绝写文件，但允许删除文件和子目录。独立 AccessCheck 显示子文件 DELETE 被拒绝、父目录 FILE_DELETE_CHILD 被允许。删除操作实际成功，不能用只检查子文件权限的测试替代。原生证据见 [父目录对照](https://github.com/lanshi17/codex-forge/actions/runs/42009045747)。

生产令牌已去除 Everyone，只保留能力、显式附加身份和 logon；因此继续调整 SID 列表不足以解释并消除该旁路。在独立实验中，移除 WRITE_RESTRICTED 并给能力显式继承只读/执行授权后，原生令牌 11 项测试通过，见[实验运行](https://github.com/lanshi17/codex-forge/actions/runs/42010478003)。这尚不是生产修复，也未证明所有权、重解析点及 IPC 边界完整。

## 兼容性冲突

现有 legacy 入口明确要求全盘读取，并以 WRITE_RESTRICTED 保留调用者普通读取权限。完整限制令牌同时限制读取，需要为读取位置显式安装授权；非管理员不一定能修改系统和工具链目录的 ACL。直接移除标志会让合法命令无法启动，不符合原成功执行契约。

目前没有经过验证的 legacy 实现能同时维持这项非管理员全盘读取兼容性和完整删除隔离。不能通过加入 Everyone、Users 或其他接受宽泛文件 ACL 的 SID 恢复读取；这会再次允许工作区外写入。单独降低完整性级别也不足以约束工作区外同等或更低完整性的目录。

## 两条可评审路线

| 路线                                  | 行为与实施范围                                                                                                                             | 兼容性及代价                                                                                                            |
| ------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------- |
| A：完整限制与显式读取授权             | 独立读取能力、完整限制令牌；按权限配置初始化读取根，保留现有写入能力和拒绝路径。系统/工具链授权通过受控管理员初始化，失败时不启动 Worker。 | 保留 legacy 执行入口，但全盘读取改为明确授权的根；新增初始化要求。需处理已有 ACL、受保护子目录和卸载恢复。              |
| B：迁移到既有 elevated 后端（已选择） | 受限任务统一由现有专用账户与权限初始化路径执行，并改用完整限制令牌；旧 legacy 入口明确返回不支持，不能自动降级到旧令牌。                   | 停止支持旧的非管理员执行路径；需迁移调用方及部署专用账户/helper。相同成功执行与越界删除场景必须在实际替代后端保留验证。 |

现有 elevated 令牌工厂也共享 WRITE_RESTRICTED 标志，单纯切换后端不能视为修复；路线 B 必须同时去掉该标志，并验证既有读取 ACL 能让正常程序启动。

用户已选择路线 B。实现必须先完成统一执行路由迁移，再让 legacy 入口显式返回不支持；不得自动降级到旧令牌。此文档不授权将失败测试改为通过，也不表示修复已经完成。原删除与成功启动回归继续作为当前阻断项，且必须在 elevated 后端上重新验证。

## 共同验收要求

- 在原 Everyone 全权夹具中拒绝工作区外写入、文件删除、目录删除与重命名；同时验证父目录 FILE_DELETE_CHILD。
- 授权工作区、TEMP/TMP 内允许创建、写入、重命名和删除，拒绝 `.git` 与明确的只读子路径；保留真实文件内容及存在性检查。
- 只读模式保持配置允许的读取，并拒绝上述所有修改；权限初始化失败不得创建子进程。
- 额外验证所有者隐式 WRITE_DAC、重新授权 ACL、重解析点、子进程继承、进程/IPC 权限以及取消后的进程树回收。
- 实际 Rust 程序与 cmd/PowerShell 在 GNU LLVM 和受支持部署环境成功执行。`0xC0000142` 仍需独立定位，不能通过放宽桌面权限绕过。
- 当前候选完整 blocking-ci 成功后才可验收；独立诊断作业、本机交叉检查及历史成功均不能替代它。

不新增第三方依赖；继续使用隔离诊断分支试验，正式变更保留在 `fix/ci-qualification`。路线 B 已获用户确认，但在完整 blocking-ci 和实际 elevated 验收完成前不宣称安全修复完成。
