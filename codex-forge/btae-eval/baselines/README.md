# 五组基线：操作流程草案，不是已验证实现

所有组共享同一源快照、需求、预算、模型、框架、权限、工具和最终独立评估。任务开始前统一要求提交影响预测（对所有组同一轻量测量动作），该测量本身可能改变自然 Vibe Coding 行为，作为反应性限制报告。

| 组 | 流程 | 不能伪装成已完成的能力 |
| --- | --- | --- |
| A 普通 AI Coding | 直接完成需求，可自发规划、测试和文档 | 不禁止自然测试以人为削弱基线 |
| B 传统文档驱动 | PRD→模块/架构设计→编码→维护常规文档 | 文档工作不免费、不由额外专家提供独享信息 |
| C SDD 风格 | Constitution→Spec→Plan→Tasks→Implement | 尚未冻结官方 Spec Kit commit，不能宣称等价产品比较 |
| D SDD+追溯 | C+实体映射、设计/代码/测试链接和依赖索引 | 实际索引/反查未实现，不能只在提示中添加关键词 |
| E BTAE | M1–M6 的实体设计、双向链接、架构变更治理、证据阻断和动态上下文 | 六项均需运行证据，当前不能真实执行完整 E |

A/B/C 的可访问语料相同；不同方法产生的设计文档数量可不同且成本全计。强制设计记录、批准、索引和 gate 是研究干预，不改变工具权限。共同 OS sandbox 及最终隐藏验收不属于某一组的特权。

需要两层验证：① 熟悉基线的独立人员检查流程是否忠实，避免 straw-man；② 验证器检查该轮机制是否实际发生。主分析按分配组保留不遵守流程的运行（intention-to-treat），另做事前规定的忠实度敏感性分析，不能删掉 E 的违规失败。

同一模型不能保证同一随机输出；记录 provider 对 seed/temperature 的支持状况。无法钉住后端版本时，使用同时间区块和模型标识监测，明确降级为服务快照实验，不能暗称精确可复现。

各组 system appendix 见 A.md–E.md。它们是 runner 待拼装的材料，**不是实际基线工具或机制实现**。
