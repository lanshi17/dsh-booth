# BTAE v1.0 候选操作规格（尚未冻结）

BTAE 是待检验方法，不是已证明的理论。现有 Forge F0 只实现了通用任务/授权/Review 领域边界，不能冒充本文件六项工程机制已经运行。

| 机制 | 输入 | 要求的输出 | 可核验约束 |
| --- | --- | --- | --- |
| M1 Design-First | 相同需求、代码、公共契约 | 事前设计与受控批准/修订记录 | patch 前设计事件；只有批准的范围可执行；门禁成本全计 |
| M2 Class/Entity Design | 类/函数/trait 的当前行为与意图 | 稳定实体 ID、职责、不变量、接口、失败语义、证据来源 | 标明规范性意图与观察所得事实；简单实体可豁免但规则事前冻结 |
| M3 双向追溯 | 需求、设计、实现、测试 | 带版本的类型化边与实体定位；正反向查询 | 链接不仅存在，还要语义正确；无效链接不得算覆盖 |
| M4 架构演进 | 公共约束、底层依赖发现、计划变更 | 漂移报告、ADR、迁移计划和约束修订审核 | 底层发现不能在事后自动改规则让违规消失；评估规则独立冻结 |
| M5 Evidence Gate | 受控源码快照、验收条件、执行证据 | 与 HEAD/测试命令/退出码绑定的 gate 决策 | 自报成功无效；Worker 不能给自己发通过状态；不得读取隐藏测试答案 |
| M6 Context Governance | 共同可访问语料、任务和受影响图 | 可审计上下文选择、排除理由、token 账本 | 检索/索引/模型辅助选择全计费；无跨组记忆或私有 Gold |

“Bottom-Up”和“Design-First”可同时成立：先从真实代码追溯事实，区分事实与规范，提出下一步设计再编码。不能把当前代码的每个缺陷当作新的正确设计。

处理忠实度：实现时每项产生事件 source_hash、timestamp、input/output artifact digest、actor_role、token/time/cost；评估者核验时间顺序和语义抽样。仅提示词和空文档不算机制实施。五组相同通用安全工具/外部最终验收，E 的 M5 是**开发过程中可见公开检查的阻断流程**，不是 E 独享更好的隐藏评估。

## 消融

E0 全量；E1 去 M2、E2 去 M3、E3 去 M4、E4 去 M5、E5 去 M6、E6 去 M1。每组仍保持共同安全权限和外部评估，去 M5 不代表允许改主分支或跳过实验计量。

移除规则必须可实施：去 M1 时可在编码后补文档以保留 M2；去 M3 时 M6 退化到事前定义的同成本文本检索，不偷偷继续调用链接图；去 M2 不能连带删除普通需求/模块文档。若组件无法独立移除，报告为联合消融/不可识别，不能称为单机制因果效果。

逐项移除仅估计全体系其余组件存在时的条件贡献。核心协同先做 M2×M3 的 2×2（其余机制固定），用交互对比 (Y11−Y10)−(Y01−Y00)。随后再评估 M3×M5；不直接穷举 2^6，也不对小样本所有交互做事后筛选。

本次没有执行消融：没有任何 ablation 效果或初步收益结论。见 reports/ABLATION-PLAN.md 的待运行清单。
