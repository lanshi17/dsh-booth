Delivery is an engineering-only, first-round task collector. It exports only frozen public seed and one arm SOP. Direct bwrap argv uses unshare-all, private HOME/tmp/state, read-only public input and executable, writable exported workspace; host project/home/evaluator never mounted. A trusted optional runtime bundle is read-only at /bundle; it is deployment input, not auto-discovered. A trusted dedicated profile supplies only explicit cordis.yml and cordis.patch.yml, capped and regular files; operator remains responsible for public config content. Default network is disabled; explicit --share-network enables engineering smoke only, with no endpoint allowlist. Environment is rebuilt; reserved HOME/PATH/DSH_* cannot be overridden by pass-env. No shell, model call by default, retry, Worktree, formal Observation or approval. Bwrap failure never falls back.

S1 collect-task binds manifest + exact planned task/arm/repeat, source snapshot, SOP and prompt; rejects round>1 instead of resetting trajectories. Fixture success changes only exported workspace; sealed snapshot retained and verify-task validates hashes and plan/source identity. hidden_test_result / empirical_task_success null, billing_verified false.
S2 Fixture probes cannot read host canary or other-arm input; input/executable are read-only, host environment absent, loopback listener unavailable by default. Per-run workspace/state never shared. Malicious filenames / profile symlinks / overlapping source-output-deployment paths rejected before writable export. Trusted deployment bundle content and /usr are not hashed as a frozen container image; no production environment freeze claim.
S3 Existing output rejected; started receipt survives invalid seed or execution/setup interruption. Malformed/nonzero/timeout/cancel collector outcomes retained with post-run snapshot when possible, never converted to task success. Bounds: live process limits plus max 64 MiB / 4096 collected files; setup/snapshot time outside live wall deadline explicitly, no end-to-end/hard token/cgroup quota claim.
S4 verify-task rejects edits, deletions, extra files, wrong manifest/task identity, changed SOP, invalid relative paths, symlinks and inconsistent process receipt. Hashes protect accidental change on trusted host, not a malicious host rewriting all hashes. Profile/session writes remain private run artifacts and must not be committed/published. Incomplete runs have started but no task.json and are not accepted.
S5 CLI runs fixture without model; exit0 only process completed plus sealed task receipt, other terminal outcomes exit1. verify-task never calls model. Existing 73 tests remain passing and readiness remains exit1.

Failure model: filesystem disclosure/contamination -> hostile real-process probes; evidence tamper/reset -> negative tests; timeout/descendants -> existing live collector tests plus task-level timeout/cancel; overwrite -> create-once collision.
